# Интеграция главного проекта с Meter OCR

## Назначение

Meter OCR — отдельный сервис распознавания фотографий водосчётчиков. Он принимает
одно изображение и сразу возвращает JSON с:

- полным результатом PaddleOCR: текст, confidence и координаты;
- извлечённым показанием механического счётчика, если оно обнаружено;
- диагностикой ошибки, если распознавание не удалось.

Сервис не хранит загруженные изображения и не обращается к внешним API во время
распознавания.

## Развёртывание новой версии

Контракт `POST /ocr` не изменён: входом остаётся поле `file`, а общий OCR
`full_text`/`items` формируется тем же PaddleOCR. Заменён только внутренний
этап `meter_reading`: он сначала ищет в оттенках серого ряд из восьми крупных,
регулярно расположенных барабанов (или внешний прямоугольник всего табло), затем
использует EasyOCR и резервный PaddleOCR для слабоконтрастных цифр. Поэтому
серийный номер не должен подменять показания. Для неподтверждённых позиций
возвращается `X`.

При первом старте контейнер скачает также CPU PyTorch и модель EasyOCR
`english_g2`; файл сохраняется в существующем Docker volume `paddle-models`
в `/app/models/easyocr`. Серверу нужен доступ в интернет на этот первый старт.
Последующие рестарты работают из volume. Не удаляйте volume при обычном обновлении.

Оставьте `OCR_WORKERS=1`: модели загружены один раз и выполняются последовательно.
Для сервера рекомендуется от 8 ГБ RAM и 10 ГБ свободного диска для образа,
слоёв пакетов и моделей. Настройте timeout клиента не меньше 120 секунд на
первый запрос после старта. Новый reader рассчитан на механический ряд из
5 целых и 3 дробных барабанов; электронные дисплеи и стрелочные шкалы не входят
в его область применения.

## Параметры подключения

| Параметр | Значение |
|---|---|
| Базовый URL | `https://ocr.poverka-bot.ru` |
| Метод | `POST` |
| Endpoint | `/ocr` |
| Формат тела | `multipart/form-data` |
| Поле с файлом | `file` |
| Авторизация | HTTP-заголовок `X-API-Key` |
| Поддерживаемые форматы | JPG, JPEG, PNG, WEBP, BMP |
| Предельный размер файла | 15 MiB |
| Рекомендуемый timeout | 120 секунд |

Ключ хранится только в переменной окружения главного проекта. Не добавляйте его в
репозиторий, фронтенд, логи или текст ошибок.

```env
OCR_API_URL=https://ocr.poverka-bot.ru
OCR_API_KEY=получить_у_администратора
OCR_HTTP_TIMEOUT_MS=120000
```

Клиентский браузер не должен обращаться к OCR напрямую: ключ должен оставаться на
backend/worker. Фото отправляет серверная часть главного проекта.

## Node.js: пример вызова

Пример рассчитан на Node.js 18+ с глобальными `fetch`, `FormData` и `Blob`.

```ts
import { readFile } from "node:fs/promises";

const OCR_API_URL = process.env.OCR_API_URL!;
const OCR_API_KEY = process.env.OCR_API_KEY!;
const OCR_TIMEOUT_MS = Number(process.env.OCR_HTTP_TIMEOUT_MS ?? 120_000);

export async function recognizeMeter(filePath: string, filename: string) {
  const bytes = await readFile(filePath);
  const form = new FormData();
  form.append("file", new Blob([bytes], { type: "image/jpeg" }), filename);

  const response = await fetch(`${OCR_API_URL}/ocr`, {
    method: "POST",
    headers: { "X-API-Key": OCR_API_KEY },
    body: form,
    signal: AbortSignal.timeout(OCR_TIMEOUT_MS),
  });

  const body = await response.json().catch(() => null);
  if (!response.ok) {
    throw new Error(`OCR request failed: HTTP ${response.status}; ${JSON.stringify(body)}`);
  }
  return body;
}
```

Если файл уже находится в памяти как `Buffer`, вместо `readFile` используйте:

```ts
form.append("file", new Blob([imageBuffer], { type: mimeType }), originalFilename);
```

Не передавайте вручную заголовок `Content-Type`: `fetch` сам добавит boundary для
`multipart/form-data`.

## Контракт успешного ответа

Успешный HTTP-ответ содержит **ровно два поля**. Подробные confidence,
координаты, статусы и техническая диагностика не возвращаются. Фрагменты общего
OCR с одиночной буквой или знаком `=` исключаются. `meter_reading` — строка с
ведущими нулями и возможными `X`, либо `null`.

```json
{
  "ocr": ["СЧЕТЧИК", "123.456"],
  "meter_reading": "123.456"
}
```

Для прикладной логики используйте следующие поля:

```ts
const result = await recognizeMeter(path, filename);
const reading = result.meter_reading;
// reading — строка, например "123.456", либо null.
// Не преобразовывать автоматически в number: важны ведущие нули.
```

## Ошибки HTTP и повторы

| Код | Причина | Поведение клиента |
|---|---|---|
| `200` + `status: "success"` | OCR завершён | Обработать результат. |
| `200` + `status: "error"` | Файл не удалось прочитать или OCR упал для него | Не повторять автоматически; показать/зафиксировать ошибку. |
| `401` | Нет или неверен `X-API-Key` | Не повторять; проверить секрет в окружении. |
| `413` | Изображение больше 15 MiB | Не повторять; уменьшить/сжать файл. |
| `415` | Неподдерживаемый формат | Не повторять; конвертировать изображение. |
| `429` | Внутренняя очередь заполнена | Повторить с задержкой из заголовка `Retry-After` (сейчас 5 секунд). |
| `503` | OCR-модели ещё запускаются или сервис временно недоступен | Повторять с экспоненциальной задержкой. |
| Сетевая ошибка / timeout | Нет связи или ответ слишком долгий | Допускается до 2 повторов с задержкой; запрос идемпотентен, но повторно потребит CPU. |

Для `429`, `503` и сетевых сбоев используйте ограниченное число повторов и backoff,
например 2, 5 и 10 секунд. Не отправляйте неограниченные повторы и не создавайте
внутреннюю очередь без лимита.

## Нагрузка и параллельность

Сервис принимает до 100 одновременно активных запросов (включая ожидающие) и
выполняет OCR одним CPU-worker'ом. Это намеренное ограничение: модели не дублируются
в памяти и сервер не перегружается при всплеске запросов.

Если главный проект обрабатывает много фотографий, он должен:

1. Ограничить собственную параллельность отправки задач.
2. Обрабатывать `429` как временную ошибку.
3. Сохранять результат OCR вместе с фото/заявкой после успешного ответа, чтобы не
   распознавать один и тот же файл повторно.
4. Не ждать OCR в критичном HTTP-запросе пользователя, если это не обязательно;
   предпочтительнее выполнять задачу в существующем `photo-worker`.

## Проверка доступности

```bash
curl https://ocr.poverka-bot.ru/healthz
```

Ожидаемый ответ:

```json
{"status":"ok","ocr_workers":1,"max_inflight_requests":100}
```

`/healthz` не требует ключа и предназначен только для мониторинга доступности.

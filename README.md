# Локальный OCR фотографий водосчётчиков

Windows x64, Python 3.11, CPU. Программа сохраняет весь найденный текст,
confidence и координаты в отдельный UTF-8 JSON для каждого снимка. Дополнительно
выделяет показания механического счётчика в `meter_reading`. Сырой OCR не исправляется. Фотографии никуда не отправляются.
LLM, облачные API, платные сервисы, база данных и веб-интерфейс не используются.

## Установка в PowerShell

Установите Python 3.11 x64 с python.org. Откройте PowerShell в папке `meter-ocr`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

Если PowerShell запрещает активацию, менять политику исполнения необязательно:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

В текущей рабочей копии окружение Python 3.11 уже создано и зависимости установлены;
его можно запускать последней командой. Для его создания использовался `uv`, который
скачал интерпретатор в `.python`. Эта папка нужна существующему окружению; для новой
установки по инструкции выше `uv` не требуется. Окружение нельзя переносить на другой
компьютер — там создайте его заново.

`requirements.txt` фиксирует весь проверенный набор зависимостей для Windows/Python 3.11,
включая PaddleOCR **3.7.0**, CPU PaddlePaddle **3.3.1**, PaddleX **3.7.2**,
Pillow **12.3.0**, NumPy **2.3.5**. GPU-пакет не устанавливается.
Если импорт PaddlePaddle сообщает об отсутствующей DLL, установите Microsoft Visual
C++ Redistributable 2015–2022 x64 с сайта Microsoft и повторите запуск.

## Использование

Поместите фотографии в `input` и выполните:

```powershell
python main.py
python main.py --input input --output output --overwrite
```

Без `--overwrite` любой существующий JSON пропускается, включая JSON со статусом
`error`. После исправления причины ошибки повторите запуск с `--overwrite`.
Если все JSON уже существуют, модели вообще не загружаются.

По умолчанию папки `input`, `output`, `models` расположены рядом с `main.py` и создаются
автоматически. Явно заданные относительные `--input` и `--output` считаются относительно
текущей папки PowerShell. Пути с пробелами заключайте в кавычки.

Обрабатываются `.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp` без учёта регистра расширения,
только файлы непосредственно в папке. Исходники не меняются. Для анимированного WebP
читается первый кадр. Например, `input/meter_001.jpg` даёт `output/meter_001.json`.
Русские имена поддерживаются. При совпадении основ имён (`meter.jpg` и `meter.png`)
программа прекращает запуск с понятной ошибкой: переименуйте один из файлов,
иначе формат `meter.json` не позволяет сохранить оба результата независимо.

## Модели и автономная работа

Используются точные имена:

- Детектор: `PP-OCRv5_mobile_det`.
- Распознаватель: `cyrillic_PP-OCRv5_mobile_rec` — компактная модель для кириллицы,
  английского текста и цифр. Файл весов распознавания около 8 МБ; полный кэш больше.

PaddleOCR 3.7.0 выбран как актуальный стабильный выпуск из PyPI на момент реализации.
Модели указаны явно: смена модели по умолчанию в библиотеке не меняет используемые веса.
Используется API 3.x `PaddleOCR(...).predict(...)` и поля `rec_texts`, `rec_scores`,
`rec_polys`; устаревший вызов `.ocr()` не используется.

Первый запуск требует интернет для загрузки официальных весов. Кэш PaddleX принудительно
направлен через `PADDLE_PDX_CACHE_HOME` в `models`, фактические файлы:

```text
models/official_models/PP-OCRv5_mobile_det/
models/official_models/cyrillic_PP-OCRv5_mobile_rec/
models/official_models/en_PP-OCRv5_mobile_rec/
```

После успешной загрузки всех трёх моделей распознавание работает без сети. Проверка
доступности серверов отключена. По умолчанию источник загрузки — официальный BOS;
его можно переопределить переменной `PADDLE_PDX_MODEL_SOURCE` до запуска.
Снимки остаются локальными; интернет нужен только для установки библиотек и весов.
Вывод скачивания перенаправлен в `models/download.log`; при новой инициализации лог
перезаписывается. Отдельные краткие диагностические сообщения нативных библиотек
могут оставаться в консоли.

## Изображения, координаты и ограничения

Pillow применяет EXIF-ориентацию и преобразует изображение в RGB; альфа-канал
накладывается на белый фон. В PaddleOCR передаётся непрерывный массив BGR.
В приложении уменьшения разрешения нет. Детектор настроен с `limit_type=min`
и минимальной стороной 64; PaddleX округляет размеры для сети и ограничивает
максимальную сторону 4000 пикселями. Для снимка 4032 пикселя это изменение менее 1%;
на очень больших панорамах уменьшение заметнее, и мелкий текст может потеряться.
Распознаватель использует собственное масштабирование вырезанных строк.

Координаты и `image.width/height` относятся к изображению **после EXIF**, начало координат
слева сверху, x вправо, y вниз. Общий поворот документа и геометрическое выпрямление
отключены, чтобы сохранить эту систему координат. Классификатор перевёрнутых строк
также отключён; перевёрнутые, вертикальные и сильно наклонённые надписи могут читаться хуже.

Четыре точки `polygon` сохраняются в порядке PaddleOCR. `bbox` вычисляется как минимум
и максимум координат четырёх точек. Координаты — обычные числа JSON (могут быть дробными).
Порядок приближённый: сверху вниз, в пределах близких по высоте строк слева направо.
Это не анализ макета и не семантическая группировка.

Проверенный словарь модели содержит русские буквы, латиницу, цифры, `№`, `/`, `-`, `.`.
Наличие символа в словаре не гарантирует его распознавание. Блики, размытие, мелкий
шрифт, надписи по окружности и механические барабаны дают пропуски и ошибки; например,
модель может спутать латинскую и кириллическую букву. На реальном тестовом снимке
длинный ряд цифр распознан лишь частично. Универсальная модель не обучена специально
для счётчиков. Полнота и точность не гарантируются.

Порог confidence распознавания установлен в `0.0`, дополнительной фильтрации нет:
сохраняются все строки, возвращённые OCR, в том числе ненадёжные или пустые.
Детектор всё равно использует свои пороги поиска текста. Confidence — оценка модели
от 0 до 1, а не гарантия правильности строки.

## JSON и ошибки

В каждом JSON: `source_file`, `status`, `image`, `ocr_engine`, `full_text`, `items`,
`items_count`, `processing_ms`, `error`. У каждой строки — `text`, `confidence`,
`polygon`, `bbox`. `full_text` в точности повторяет `items[].text` в том же порядке.
`ocr_engine.version` берётся из установленного пакета; `model` содержит имя распознавателя,
дополнительное `detection_model` — имя детектора. Если пакет отсутствует, версия — `null`.

JSON пишется с `ensure_ascii=False`, отступом 2, без NaN и Base64. Запись атомарная:
временный файл заменяет целевой только после успешной сериализации.

Нечитаемый файл даёт `ImageReadError` и `image: null`. Ошибка OCR даёт `OCRError`,
ошибка загрузки модели — `OCRInitializationError`; если снимок прочитан, его размеры
сохраняются. При сбое общей инициализации попытка загрузки не повторяется на каждом
снимке, но каждый получает свой JSON. Обработка других файлов продолжается.
Ошибка записи JSON выводится в консоль: создать файл в недоступной папке невозможно.
Снимок без текста — `success` с пустыми списками.

`processing_ms` включает чтение снимка и OCR, но не общую загрузку моделей и запись JSON.
Коды завершения: `0` — успешно/всё пропущено, `1` — были ошибки файлов или OCR,
`2` — ошибка аргументов, папок или конфликт имён.

## Проверки

```powershell
python -m unittest -v test_main
```

Тесты без загрузки моделей проверяют EXIF/BGR, все входные форматы, русские имена,
координаты, NumPy/JSON, пустой результат, ошибки, продолжение обработки, skip/overwrite.
В текущей рабочей копии также есть `verification/input` и `verification/output`:
три копии реальных фотографий, контрольное изображение с текстом, белое изображение
и намеренно испорченный JPEG. Проверить эту подборку повторно:

```powershell
python verify_outputs.py
```

Этот сценарий перезаписывает только тестовые JSON, блокирует сеть в OCR-процессе,
проверяет JSON, пропуск, перезапись и хеши исходников. Он требует уже скачанные модели
и подготовленную тестовую подборку этой рабочей копии. Подробности в `TEST_REPORT.md`.

## Показания механического счётчика (доработка)

В JSON добавлен **`meter_reading`**, отдельно от исходных `items` и `full_text`:

```json
"meter_reading": {
  "value": "00X30.68X",
  "status": "partial",
  "decimal_places": 3,
  "digits_count": 8,
  "cells": [],
  "error": null,
  "model": "en_PP-OCRv5_mobile_rec"
}
```

Это пример формата. В реальном JSON `cells` содержит каждую ячейку слева направо:
`digit`, `confidence`, `polygon`, `ocr_candidates`. Для `X` confidence равен `null`.
`value` всегда строка: ведущие нули и `X` сохраняются. Три последних разряда всегда
считаются дробными по заданному пользователем правилу; единица измерения не угадывается.

Число ячеек **не фиксируется равным восьми**. Алгоритм ищет крупную цифровую область
среди предложений общего OCR, выравнивает её, находит три красных дробных барабана
и измеряет повторяемость вертикальных окон слева. По расстояниям оценивается число
целых разрядов (поддерживаются 2–12 целых + 3 дробных). Для ряда с небольшой перспективой
шаг целых и дробных окон может различаться. Длина распознанного текста не задаёт число ячеек.

Для каждого окна отдельная модель `en_PP-OCRv5_mobile_rec` выполняет четыре прохода:
две бинарные вырезки с удалением рамки и две цветные. Принимается только одна цифра
0–9: нужно согласие как минимум двух результатов с confidence >=0.85. Для целых
разрядов также допускаются два совпадающих результата >=0.65, если хотя бы один >=0.90
и нет другой цифры >=0.85. У дробных разрядов действует более строгий первый вариант.
Это эвристические пороги, не калиброванная вероятность правильности. Противоречия,
буквы, пустые строки, слабые результаты и несколько символов вместо цифры дают `X`.

Статусы:

- `recognized`: все позиции получили цифры; это не гарантия правильности показания.
- `partial`: поле найдено, в нём есть `X`.
- `not_found`: геометрия/цвет не подтверждены, `value` и `digits_count` равны `null`.
- `error`: сбой дополнительного распознавания; сырой OCR сохраняется независимо.
- `unavailable`: исходный снимок или общий OCR недоступен.

**Границы текущей версии:** алгоритм рассчитан на механические счётчики с тремя
красными дробными барабанами, как на присланных примерах. Он использует прямоугольную
периодическую структуру и цвет, а не обученный детектор окон. Полностью чёрные ряды,
электронные дисплеи, сильная перспектива, нестандартные цвета или пропуск всей области
общим OCR могут дать `not_found`. При отсутствии надёжной оценки числа разрядов нельзя
создавать строку из произвольного числа `X`, поэтому возвращается `null`.
Высокий confidence тоже может соответствовать неверной цифре. Переходящие барабаны
не интерпретируются с учётом переноса разряда; сомнительные показания проверяйте вручную.

Дополнительная модель занимает около 8 МБ весов и уже скачана в этой рабочей копии.
Все вычисления остаются локальными, на CPU. Новые Python-зависимости не нужны.

Запуск двойным щелчком `start.bat` сохраняет прежний режим пропуска готовых JSON.
Для обновления старых результатов запустите **`reprocess.bat`** или:

```powershell
.\.venv\Scripts\python.exe main.py --overwrite
```

Новые тесты: `python -m unittest -v test_main test_meter_reading`.
Результаты проверки пяти присланных фотографий записаны в `output`.

# Meter OCR

Локальная CLI-программа для пакетного распознавания фотографий водосчётчиков на Windows. Приложение работает на CPU, сохраняет весь найденный текст и его координаты в JSON, а также отдельно пытается извлечь показание механического счётчика.

Данные обрабатываются локально: облачные API, LLM, база данных и веб-интерфейс не используются. Интернет нужен только при установке зависимостей и первом скачивании моделей.

## Production API (Docker)

Сервис предназначен для вызова главным проектом на том же сервере. Поднимите его из
папки проекта:

```bash
docker compose up -d --build
docker compose logs -f meter-ocr
```

Контейнер публикует OCR только на `127.0.0.1:12354`; для внешнего доступа направьте
на него отдельный HTTPS-домен через Caddy. Главный проект обращается к
`https://ocr.poverka-bot.ru/ocr` с `multipart/form-data` и полем файла `file`; ответ —
готовый JSON в контракте CLI. Перед запуском скопируйте `.env.example` в `.env` и
создайте длинный случайный `OCR_API_KEY`. Каждый вызов `/ocr` обязан передавать этот
ключ в заголовке `X-API-Key`.

```bash
curl -H "X-API-Key: $OCR_API_KEY" -F "file=@meter.jpg" https://ocr.poverka-bot.ru/ocr
curl https://ocr.poverka-bot.ru/healthz
```

При запуске контейнер загружает модели до перехода в состояние ready. Они сохраняются в
именованном томе `paddle-models`, поэтому следующая перезагрузка не скачивает их снова.
Во время инициализации `/healthz` и `/ocr` возвращают `503`.

В контейнере ровно один процесс Uvicorn и один предварительно загруженный набор:
PaddleOCR для надписей/поиска строки, EasyOCR для отдельных барабанов и
PaddleOCR как резервный распознаватель отдельных слабоконтрастных цифр. `OCR_WORKERS=1` последовательно выполняет inference, что безопаснее для CPU и не
дублирует память моделей. До 100 одновременных HTTP-запросов принимаются в ограниченную
очередь (`MAX_INFLIGHT_REQUESTS`); следующий получает `429` и заголовок `Retry-After`.
При достаточных CPU/RAM можно увеличить `OCR_WORKERS`, предварительно проверив
производительность и потребление памяти. Максимальный размер одного файла задаётся
`MAX_UPLOAD_BYTES` (по умолчанию 15 MiB). Фото в сервисе не сохраняются на диск.

## Возможности

- обработка `.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`;
- исправление EXIF-ориентации и корректная обработка прозрачности;
- распознавание кириллицы, латиницы и цифр через PaddleOCR;
- сохранение текста, confidence, четырёхугольника и bounding box каждой строки;
- автоматическое выравнивание ряда механических барабанов по перспективе или наклону;
- распознавание каждой цифры в градациях серого несколькими вариантами препроцессинга;
- обозначение сомнительных цифр символом `X` вместо угадывания;
- пакетная обработка с пропуском готовых результатов;
- атомарная запись JSON и продолжение работы после ошибки отдельного файла;
- автономное распознавание после загрузки моделей.

## Требования

- Windows x64;
- Python 3.11;
- CPU;
- Microsoft Visual C++ Redistributable 2015–2022 x64, если PaddlePaddle сообщает об отсутствующей DLL.

Основные зависимости:

- `paddleocr==3.7.0`;
- `paddlepaddle==3.3.1`;
- `paddlex==3.7.2`;
- `opencv-contrib-python==4.10.0.84`;
- `Pillow==12.3.0`;
- `numpy==2.3.5`;
- `EasyOCR==1.7.2` и CPU-версии PyTorch/Torchvision.

Полный зафиксированный набор находится в `requirements.txt`.

## Запуск

Поместите изображения непосредственно в папку `input` и выполните:

```powershell
python main.py
```

Пользовательские каталоги и принудительная перезапись:

```powershell
python main.py --input "D:\Photos" --output "D:\OCR"
python main.py --input input --output output --overwrite
```

Для обычного повторного запуска с перезаписью используйте готовый batch-файл:

```cmd
reprocess.bat
```

`reprocess.bat` автоматически вызывает `start.bat --overwrite`, использует локальное окружение `.venv` и запускает обработку стандартных папок `input` и `output`. При необходимости дополнительные аргументы можно передать ему:

```cmd
reprocess.bat --input "D:\Photos" --output "D:\OCR"
```

## Проверка только показаний счётчика

Новый экспериментальный алгоритм запускается отдельно от `main.py` и API:

```powershell
.\test_readings.bat
# Или напрямую:
.\.venv\Scripts\python.exe -X utf8 test_readings_only.py
```

Он каждый раз заново ищет строку и распознаёт снимки из `input`, не читает
кэш прошлых показаний, не использует имя файла при распознавании и не меняет `output`.
Результаты: `reading_test_output/report.json`, отдельные JSON, фото с контурами
барабанов, вырезки всех цифр и журнал `localization.log`.

Имена могут быть произвольными. Для **автоматической оценки** назовите файл
`целая_дробная.jpg`, например `134_952.jpg`. Дробная часть — три цифры.
Критерий: ни одной неверной цифры и не более двух `X`, включая ведущие барабаны.
Без эталонного имени в отчёте стоят `passed: null` и `wrong_digits: null`:
число неизвестных само по себе не доказывает правильность остальных цифр.
`--require-labels` запрещает запуск без эталонов.

Принцип работы:

- Сначала в оттенках серого ищется ряд из восьми крупных, одинаковых по высоте
  и почти равномерно расположенных барабанов. Это отсеивает серийные номера:
  их символы обычно мельче и не образуют регулярную цепочку. Если цифры слились
  с фоном, используется длинный прямоугольник всего табло. Только затем PaddleOCR
  ищет числовую строку как запасной ориентир.
- Строка выравнивается по четырёхугольнику или поворотом; повторяющиеся границы
  окошек задают несколько вариантов разбиения на барабаны.
- Цифры переводятся в градации серого. Адаптивная и глобальная бинаризация,
  выделение связных компонент и разные вырезки уменьшают влияние теней и рамок.
- EasyOCR читает отдельные цифры. Для слабоконтрастного шрифта его результат
  сверяется с PaddleOCR, запущенным на трёх вариантах одного барабана. Недостаточно
  подтверждённые позиции получают `X`.

**Красные/чёрные маски не используются.** Детектор текста получает исходное цветное
фото, но правила поиска не привязаны к цвету, а распознавание цифр работает в сером.
Это не гарантирует идентичный результат после любого изменения цвета фотографии.
Положение запятой задано конфигурацией: **5 целых + 3 дробных барабана**;
число целых можно изменить через `--integer-digits`. Алгоритм не определяет
число дробных разрядов автоматически и не предназначен для стрелочных шкал.
На фото с несколькими счётчиками выбирается одна крупная строка, не все приборы.

Тест использует то же окружение `.venv`, что и основной сервис. После получения
новой версии кода один раз обновите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

При необходимости задайте другой интерпретатор для поиска строки: `--seed-python PATH`.
EasyOCR-модель автоматически загрузится при первом тестовом запуске в `models/easyocr`.
Фото обрабатываются локально. YOLO и облачные API для нового теста не нужны.

Дополнительно: `--input PATH`, `--debug-dir PATH`, `--no-debug-images`.
Для сравнения со старым алгоритмом:

```powershell
.\.venv\Scripts\python.exe -X utf8 test_readings_only.py --backend legacy --debug-dir reading_test_output/legacy
.\.venv\Scripts\python.exe -X utf8 -m unittest test_main test_meter_reading test_counter_reader -v
```

Проверка 2026-09-16 на текущих шести фото дала `0013X.95X`, `0026X.14X`,
`01510.X15`, `00208.82X`, `0X777.30X`, `00280.X6X` — по 1–2 неизвестных.
Полный прогон с поиском строк и загрузкой моделей занял около 57 секунд на этом ПК.
Эти фото использовались при настройке, поэтому это **не независимая оценка качества**.
Этот алгоритм используется также в CLI и API; API-контракт не менялся.

## Аргументы основной программы

Аргументы:

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--input` | `input` рядом с `main.py` | Папка исходных изображений. |
| `--output` | `output` рядом с `main.py` | Папка результирующих JSON. |
| `--overwrite` | выключен | Перезаписать уже существующие JSON. |

На Windows также доступны:

- `start.bat` — запуск через `.venv` с пропуском готовых JSON;
- `reprocess.bat` — запуск с `--overwrite`.

Поиск файлов нерекурсивный. Если в одной папке есть, например, `meter.jpg` и `meter.png`, запуск завершится ошибкой: оба файла соответствуют одному имени `meter.json`.

Коды завершения:

- `0` — успешно или все результаты пропущены;
- `1` — при обработке одного или нескольких файлов произошли ошибки;
- `2` — ошибка аргументов, доступа к каталогам или конфликт имён.

## Модели

Используются модели:

| Назначение | Модель |
|---|---|
| Детекция текста | `PP-OCRv5_mobile_det` |
| Общее распознавание | `cyrillic_PP-OCRv5_mobile_rec` |
| Резервный поиск строки цифр | `en_PP-OCRv5_mobile_rec` |
| Распознавание отдельных барабанов | EasyOCR `english_g2` + резервный `en_PP-OCRv5_mobile_rec` |

При первом запуске модели загружаются в:

```text
models/official_models/
├── PP-OCRv5_mobile_det/
├── cyrillic_PP-OCRv5_mobile_rec/
└── en_PP-OCRv5_mobile_rec/
```

Лог инициализации записывается в `models/download.log`. После заполнения кэша программа может выполнять inference без сети. Все модели запускаются на CPU; MKL-DNN, автоповорот документа, document unwarping и классификация ориентации строк отключены.

## Как работает обработка

```text
input/*
  → чтение изображения и EXIF-коррекция
  → преобразование RGB в BGR
  → детекция текстовых областей
  → общее распознавание текста
  → проверка и сортировка OCR-результатов
  → поиск периодического ряда барабанов
  → перспективная вырезка отдельных ячеек
  → четыре варианта распознавания каждой цифры
  → консервативное голосование: цифра или X
  → атомарная запись output/<имя>.json
```

Область показаний сначала ищется среди результатов общего OCR. Если подходящей
числовой строки нет, резервный путь перебирает автоматически найденные углы,
ищет ряд окошек по геометрии и проверяет кандидаты цифровой PaddleOCR-моделью.
Ряд выравнивается перспективным преобразованием или поворотом; повторяющиеся
границы окошек формируют несколько вариантов разбиения на барабаны.

Каждый барабан приводится к градациям серого и читается EasyOCR после адаптивной
и глобальной бинаризации с несколькими вырезками. Цвет цифр не является признаком.
Подтверждённая цифра из второго варианта может дополнить `X` первого; при конфликте
выбирается вариант с более сильным повторяемым подтверждением. Неподтверждённая
позиция остаётся `X`. Текущая схема рассчитана на 5 целых и 3 дробных барабана.

## Формат результата

Для каждого входного изображения создаётся отдельный UTF-8 JSON:

```json
{
  "source_file": "meter.jpg",
  "status": "success",
  "image": {
    "width": 1350,
    "height": 1800
  },
  "ocr_engine": {
    "name": "PaddleOCR",
    "version": "3.7.0",
    "model": "cyrillic_PP-OCRv5_mobile_rec",
    "detection_model": "PP-OCRv5_mobile_det"
  },
  "full_text": ["003068"],
  "items": [
    {
      "text": "003068",
      "confidence": 0.9,
      "polygon": [[295.0, 331.0], [769.0, 249.0], [787.0, 353.0], [313.0, 435.0]],
      "bbox": {"x1": 295.0, "y1": 249.0, "x2": 787.0, "y2": 435.0}
    }
  ],
  "items_count": 1,
  "processing_ms": 13830,
  "error": null,
  "meter_reading": {
    "value": "X0030.68X",
    "status": "partial",
    "decimal_places": 3,
    "digits_count": 8,
    "cells": [],
    "error": null,
    "model": "en_PP-OCRv5_mobile_rec"
  }
}
```

`full_text` повторяет значения `items[].text` в том же порядке. Координаты относятся к изображению после EXIF-коррекции: начало находится слева сверху, `x` направлен вправо, `y` — вниз.

Статусы `meter_reading`:

| Статус | Значение |
|---|---|
| `recognized` | Для всех ячеек получены цифры. |
| `partial` | Поле найдено, но некоторые позиции представлены как `X`. |
| `not_found` | Геометрия или цвет поля показаний не подтверждены. |
| `error` | Дополнительное распознавание завершилось ошибкой; общий OCR сохранён. |
| `unavailable` | Изображение, общий OCR или цифровая модель недоступны. |

Каждый объект `meter_reading.cells[]` содержит:

- `digit` — цифру или `X`;
- `confidence` — минимальную принятую оценку либо `null`;
- `polygon` — координаты ячейки;
- `ocr_candidates` — все варианты ответа цифровой модели.

Ошибки верхнего уровня имеют тип `ImageReadError`, `OCRInitializationError` или `OCRError`. Снимок без найденного текста считается успешно обработанным и содержит пустые списки.

## Функции и классы

### `main.py`

| Функция | Назначение |
|---|---|
| `get_image_files(folder)` | Возвращает отсортированный список поддерживаемых изображений непосредственно в указанной папке. |
| `load_image(path)` | Читает изображение через Pillow, применяет EXIF-ориентацию, накладывает прозрачность на белый фон и возвращает непрерывный BGR-массив NumPy. |
| `create_engine()` | Настраивает кэш и логирование, затем создаёт CPU-конвейер общего PaddleOCR. |
| `run_ocr(engine, image)` | Запускает `engine.predict()` и материализует результаты в список. |
| `create_digit_recognizer()` | Создаёт отдельный CPU-распознаватель `en_PP-OCRv5_mobile_rec`. |
| `normalize_ocr_result(results)` | Проверяет массивы PaddleOCR, преобразует типы, формирует `polygon`/`bbox` и сортирует элементы по строкам. |
| `save_json(path, data)` | Сериализует данные без ASCII-экранирования и NaN, затем атомарно заменяет целевой JSON. |
| `process_image(path, engine, engine_info, ...)` | Обрабатывает один снимок, формирует общий OCR, показание, время и структурированную ошибку. |
| `main(argv=None)` | Разбирает CLI, создаёт папки, загружает модели один раз, обрабатывает файлы и возвращает код завершения. |

### `meter_reading.py`

| Функция | Назначение |
|---|---|
| `detect_cells(image, items)` | Ищет ряд механических окон по OCR-полигонам, геометрической периодичности и трём красным дробным барабанам. Возвращает полигоны ячеек или пустой список. |
| `crop_cell(image, polygon)` | Выпрямляет четырёхугольную область перспективным преобразованием и возвращает прямоугольный BGR-crop. |
| `empty_reading(status="not_found", message=None)` | Создаёт стандартный пустой объект `meter_reading`. |
| `recognize_reading(image, recognizer, items)` | Старый изолированный алгоритм; сохранён для обратной диагностики, но не вызывается API. |

### `verify_outputs.py`

| Функция | Назначение |
|---|---|
| `hashes(folder)` | Вычисляет SHA-256 всех непосредственных файлов каталога. |
| `run(overwrite=False)` | Запускает основной CLI на smoke-наборе в отдельном процессе с заблокированными исходящими соединениями. |
| `main()` | Проверяет skip/overwrite, JSON-контракт, координаты, ошибки, автономность и неизменность исходных файлов. |

### `test_main.py`

- `FakeEngine.predict(image)` — имитация результата PaddleOCR без загрузки моделей.
- `OCRTests.setUp()` / `tearDown()` — создание и удаление временного тестового каталога.
- `test_exif_and_bgr()` — проверка EXIF и порядка BGR-каналов.
- `test_formats_and_nonrecursive_discovery()` — проверка форматов и нерекурсивного поиска.
- `test_result_and_json()` — проверка сортировки, bbox и UTF-8 JSON.
- `test_errors_and_empty()` — проверка ошибок чтения/OCR и пустого результата.
- `test_skip_overwrite_and_continue()` — проверка пропуска, перезаписи и продолжения после ошибки.
- `test_malformed_result_rejected()` — проверка отклонения некорректного ответа PaddleOCR.

### `test_meter_reading.py`

Класс `ReadingTests` проверяет:

- размещение десятичной точки и сохранение неизвестных позиций;
- возврат `not_found` без выдуманного значения;
- отклонение конфликтующих цифр;
- сохранение общего OCR при ошибке дополнительного модуля;
- автоматическое определение количества ячеек.

## Тестирование

Модульные тесты не требуют реальных моделей:

```powershell
python -m unittest -v test_main test_meter_reading test_counter_reader
```

Интеграционная проверка использует подготовленную папку `verification`, уже скачанные модели и перезаписывает тестовые JSON:

```powershell
python verify_outputs.py
```

Сценарий блокирует сеть внутри OCR-процесса, проверяет повторный запуск, JSON-контракт и хеши входных файлов. Подробности последнего сохранённого запуска находятся в `TEST_REPORT.md`.

## Ограничения

- Это inference-проект: обучение моделей и размеченный датасет отсутствуют.
- Извлечение показаний рассчитано на механические счётчики с 5 целыми и 3 дробными барабанами; цвет цифр не используется.
- Электронные дисплеи, нестандартная геометрия окон и сильная перспектива могут дать `not_found`.
- На фото с несколькими счётчиками выбирается одна наиболее подходящая строка; электронные дисплеи и стрелочные шкалы не поддерживаются.
- Переходящие между цифрами барабаны и перенос разрядов специально не интерпретируются.
- Confidence является оценкой модели, а не гарантией правильности.
- Общий OCR сохраняется без исправления и дополнительной фильтрации; его confidence-порог равен `0.0`.
- Автоповорот строк отключён, поэтому вертикальный или перевёрнутый текст распознаётся хуже.
- Очень большие изображения могут уменьшаться внутренним препроцессором PaddleOCR.
- Полностью распознанное показание всё равно рекомендуется проверять вручную.
